## 2. 7 轴读取与对齐

正式 MCAP 读取器逐条核验元数据、schema、字段和反馈含义：

- 视频：`/observation/camera/head/color/left/encoded`。
- 执行臂：`/observation/robot/{left,right}/arm/joints`。
- 夹爪：`/observation/robot/{left,right}/gripper/joints`。

核对左右臂各 7 关节、夹爪通道、有限数值、原帧数量及严格递增时间。保留原视频解码顺序与源时钟，不用名义 FPS 重建实际时间轴。

四路反馈独立对齐到每个原视频帧，采用最近实测样本、等距选较早的策略。容差与逐帧误差记录遵循 `boundary.md` 的 C 节。保留源样本行和时间戳；不插值伪造实测反馈、不静默丢帧或修改时间消除错误。

## 3. 标准输入与冻结

每条轨迹至少记录以下字段：

| 内容 | 必要记录 |
| --- | --- |
| 身份与来源 | 唯一 key、dataset_id、episode ID、源路径和摘要、任务来源、布局声明 |
| 状态与时间 | `joint[N,D]`、`timestamps[N]`、原始帧号映射、帧数、相机与时钟来源 |
| 对齐证据 | 每路所选原行、源时间戳、有符号误差及汇总；6 轴既有对齐映射保留来源 |
| 候选 | node ID、原帧、时间、张开侧、检测依据及配置摘要 |
| 视频 | 用于示范观察/导出的源视频引用、帧/PTS 检查与摘要，像素不进入推断 |

候选必须覆盖冻结检测器产生的全部可用事件，不能按预期答案筛选。末帧事件可保留检测记录，但不作为阶段边界。准备数据被导入新运行时须校验时间、身份、来源和检测参数。

现有 6 轴 NPZ/manifest 的可运行格式见 [算法文档](JOINT_REVERSE_SUFFIX.md)。正式包读取器生成 16 维标准输入，保存原视频时钟、各流所选源行、源时间戳、有符号误差和逐帧超限记录。

## 4. 示范与数据保护

7 轴新选 10 条示范，选取、替换、逐边界参考及不确定性按 `boundary.md` 的 E 节记录。Codex 参考与模型预测分开；独立评估轨迹不得重叠模板示范，也不得用于调整参数。旧 P1 清单不作为新输入清单。

原始数据和历史产物只读。转换视频、标准化数组、候选、标注与摘要写入本库新的 `runs/`。源格式转换和媒体编码须保留原帧/时间的可追溯映射；生成大文件不入版本库。

## 5. 准备命令清单

`prepare --manifest` 接收非空 JSON 数组，各项有唯一 `key`。6 轴项引用相对清单目录的 `dataset_npz`，NPZ 包含 `joint` 和 `timestamps`；冻结候选通过 `detector_sha256` 或同目录 `detector_config.json` 验证配置并原样保留，同时保留 joint 来源映射，不从另一条反馈序列重建候选。尚无候选的新数据执行检测。7 轴项提供 `source_mcap` 和 `source_metadata`，两者均须在配置的数据根目录内；读取器核对元数据 DOF、schema、关节名和原帧时间，并生成新的源视频副本。

配置中的相对路径相对 YAML 所在目录解析；清单中的相对路径相对清单目录解析。准备运行记录配置、输入摘要、检测结果及对齐依据，拒绝覆盖历史目录。
