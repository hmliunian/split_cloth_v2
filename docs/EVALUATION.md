# 验证与回归

当前没有新库算法或测试执行结果。本文件定义开发时应验证的行为，以及可使用的已知事实。

## 1. 000543 的确认范围

用户在本轮对旧试跑给出判断：“000543 只有这个划分是正确的。”对应旧运行 `stage3_anchor_diag5_20261023` 展示的三个候选结束帧为 **400 / 485 / 562**。这是用户对已展示划分的确认，尚不是重新逐帧标定夹爪物理释放的独立测量。

原视频 681 帧，0 基闭区间应展开为：

| 阶段 | 原始帧闭区间 |
| --- | --- |
| stage1 | 0–400 |
| stage2 | 401–485 |
| stage3 | 486–562 |
| stage4 | 563–680 |

旧候选帧依次是 `22, 76, 167, 169, 273, 274, 399, 400, 485, 562, 626`。其中 562 帧右爪张开、左爪闭合；新契约允许该节点，不得因左爪闭合拒判。400 和 485 帧两爪均为张开状态。

如果新模型依次正确匹配，预期调用轨迹是：

```text
626 / target_stage=3 → skip（移走相关）
562 / target_stage=3 → match
485 / target_stage=2 → match
400 / target_stage=1 → match → 停止
```

此序列可作为模拟 provider 的控制流测试；它不代表新 VLM 已经给出这些回答。真实运行必须保留实际回答，逐个与画面核对。

回归检查先要求边界仍为 400/485/562。若变化，报告差异并检查候选、图像和判断，不静默扩大容差、改期望或增加针对 episode 的规则。期望帧只进入评估，不进入 prompt、候选生成或运行清单。

P1 交付验收：

- 10 个不同 episode 的完整、可播放 MP4，布局遵守 [VISUALIZATION.md](VISUALIZATION.md)，每个附同名导出 JSON；另有 `exports.json` 和 `video_verification.json`。
- 每个视频的帧数与输入清单对应，总计 6568 帧；逐帧相对 PTS、编码和尺寸核验通过。000543 保留边界回归与显示切换检查。
- `summary.json` 和 `phase1_report.md` 覆盖全部 10 条：边界、程序状态、人工复核状态、错误/未知原因、逻辑请求数、HTTP 尝试数、tokens、耗时及视频路径。
- `needs_review` 和模型无法确认的轨迹仍导出可见的未知/候选状态；不得只挑好结果，也不得用同轨迹多版本或裁剪片段凑足 10 条。
- 视频缺失或验证失败表示交付尚未完成，需要修复。MP4 全部交付与算法是否全部正确分开评价；不因样本边界错误就从报告移除。

## 4. 必须覆盖的离线行为

实现时用小型合成 state、临时视频/目录和模拟 provider 覆盖真实失效模式。不要写仅复述常量的测试。

| 范围 | 应检查的场景 |
| --- | --- |
| Dataset | 只接收已登记叠衣来源；其他任务在准备阶段拒绝且不调用 VLM。 |
| 对齐 | 少一行、帧偏移、时间倒序、非有限反馈、错误维度报错。 |
| 检测 | 左或右单独张开；另一爪闭合；噪声不重复建点；持续张开；初始已开。 |
| 合并 | 同帧两臂合并，399/400 这种不同帧事件分别保留。 |
| 平台 | 保存平台首帧与确认帧，不能用较晚确认帧替换候选。 |
| 图像 | CANDIDATE 精确对应原帧；上下文去重、截断、按正序排列。 |
| 搜索 | 初始为 3；只有 match 才递减；skip/uncertain 保持目标；选到 1 立刻停止。 |
| 耗尽 | 无 stage3 时全空；缺 stage2 时保留 stage3；槽位不压缩。 |
| 结构 | 错 node_id、错 stage、非法 decision 或自由帧号不得写入槽位。 |
| 末帧 | 候选在 N-1 时记录跳过，不能生成空 stage4。 |
| 标签 | 边界帧归前段，下一帧归后段；长度 N；缺槽位时保留未知。 |
| 缓存恢复 | 中断重放正确目标；改变 prompt、模型、采样或检测配置时缓存不误命中。 |
| 副作用 | 只写指定运行目录；原始输入、旧预测、人工记录保持不变。 |
| MP4 导出 | 全帧数与相对 PTS 保持、非零源起点、边界高亮、未知显示、标签保护和同名导出保护；详见 [VISUALIZATION.md](VISUALIZATION.md)。 |

默认 `pytest` 检查完全离线。节点存在不保证视觉正确，模拟 provider 通过不保证真实模型能识别形态。

## 5. 真实实验步骤

1. 按第一阶段清单离线准备 10 条，检查数据轴、候选数、节点图和最多逻辑请求数；运行所有相关离线检查。
2. 冻结配置、完整 prompt、模型和源摘要，在真实调用已授权的范围内先运行 000543。
3. 查看实际调用顺序、三个边界和每次证据；在同一冻结配置下继续完成另外九条。配置改变则使用新 run，最终交付的 10 条使用同一版本。
4. 为 10 条叠衣轨迹分别导出完整复核 MP4，仿照旧版画面、阶段面板和时间线；附状态、复核原因、调用与 token 统计。重新解码，逐条按清单核对帧数、相对 PTS，总计 6568 帧，保存验证记录。
5. 按结果报告：哪些保持/改善，哪些仍错或未知，错误来自候选缺失、局部图不足、形态判断还是映射。未经人工确认不能把程序 complete 计为正确。

节点漏检与 VLM 判错要分别诊断：正确形态附近无候选时先检查 state；有正确候选却 skip/uncertain 或匹配了错误节点时检查图像与 prompt。避免在同次对照中同时改检测和视觉策略而无法归因。
