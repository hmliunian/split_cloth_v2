## 4. 必须覆盖的离线行为

实现时用小型合成 state、临时视频/目录和模拟 provider 覆盖真实失效模式。不要写仅复述常量的测试。

| 范围 | 应检查的场景 |

| Dataset | 只接收已登记叠衣来源；其他任务在准备阶段拒绝且不调用 VLM。 |
| 对齐 | 少一行、帧偏移、时间倒序、非有限反馈、错误维度报错。 |
| 检测 | 左或右单独张开；另一爪闭合；噪声不重复建点；持续张开；初始已开。 |
| 合并 | 同帧两臂合并，399/400 这种不同帧事件分别保留。 |
| 平台 | 保存平台首帧与确认帧，不能用较晚确认帧替换候选。 |
| 图像 | CANDIDATE 精确对应原帧；上下文去重、截断、按正序排列。 |
| 搜索 | 初始为 3；只有 match 才递减；skip/uncertain 保持目标；选到 1 立刻停止。 |

| 缓存恢复 | 中断重放正确目标；改变 prompt、模型、采样或检测配置时缓存不误命中。 |
| 副作用 | 只写指定运行目录；原始输入、旧预测、人工记录保持不变。 |
| MP4 导出 | 全帧数与相对 PTS 保持、非零源起点、边界高亮、未知显示、标签保护和同名导出保护；详见 [VISUALIZATION.md](VISUALIZATION.md)。 |

## 5. 真实实验步骤

1. 按第一阶段清单离线准备 10 条，检查数据轴、候选数、节点图和最多逻辑请求数；运行所有相关离线检查。
2. 冻结配置、完整 prompt、模型和源摘要，在真实调用已授权的范围内先运行 000543。
3. 查看实际调用顺序、三个边界和每次证据；在同一冻结配置下继续完成另外九条。配置改变则使用新 run，最终交付的 10 条使用同一版本。
4. 为 10 条叠衣轨迹分别导出完整复核 MP4，仿照旧版画面、阶段面板和时间线；附状态、复核原因、调用与 token 统计。重新解码，逐条按清单核对帧数、相对 PTS，总计 6568 帧，保存验证记录。
5. 按结果报告：哪些保持/改善，哪些仍错或未知，错误来自候选缺失、局部图不足、形态判断还是映射。未经人工确认不能把程序 complete 计为正确。

节点漏检与 VLM 判错要分别诊断：正确形态附近无候选时先检查 state；有正确候选却 skip/uncertain 或匹配了错误节点时检查图像与 prompt。避免在同次对照中同时改检测和视觉策略而无法归因。

## 9. v2 验证要求

### 离线程序行为

在第4节原有检测、映射、帧归属和输入保护检查基础上，v2 沿用单候选的固定时间上下文，接入 expert example 与外置 prompt，并检查以下场景：

| 范围 | 待检查的真实失效模式 |
| --- | --- |
| 候选与上下文 | `CANDIDATE` 精确对应原帧；按 PTS 抽取固定时间上下文，首尾截断后去重，按正序发送且正负时间偏移正确。 |
| 少量候选 | 无可选候选时零 VLM 调用；仅有一个或两个时仍正常倒序判断、保留匹配槽位，耗尽后缺槽待复核，标签全未知。 |
| 外置 prompt | 相对 YAML 解析 `prompt_file`，从不同工作目录启动也加载同一文本；缺失、空白或非 UTF-8 文件在发送前报错，不回退旧 prompt。 |
| 示例与预算 | 每个阶段准确对应一张示例，候选与上下文至多五张，加示例至多六张；缺图、无法解码、映射不全、预算不足在发送前报错。 |
| 发送标签 | 示例具有阶段标签而无本轨迹时间；当前节点唯一标为 `CANDIDATE`，上下文标为 `BEFORE` / `AFTER`，本轨迹图像按正序发送。 |
| 顺序与上下文 | 每个候选正式判断最多一次，上下文不接受单独判断；`match` 后才切换目标及示例；`skip`/`uncertain` 不重问；选到 stage1 即停止。 |
| 响应校验 | 返回其他候选 ID、上下文帧号、示例标识、错阶段或额外字段报执行错误，不静默修正为合法选择。 |
| 冻结与恢复 | prepare 后改动源 prompt 或示例不改变已有运行的冻结输入；修改冻结副本拒绝恢复；新示例、映射、上下文取样或 prompt 的新请求不复用旧缓存。 |
| 缺槽说明 | stage3 未找到时，stage2/1 标明未进入搜索；已搜索但耗尽与证据不确定可追溯到 trace，不能等同于视频缺少动作。 |

使用合成候选、临时图片和模拟 provider 验证上述程序行为，执行 `.venv/bin/python -m pytest -q` 并记录实际结果。模拟测试只能证明取样、顺序与接口约束，不能证明 VLM 理解了“刚完成”或已纠正用户指出的错误。

### 真实模型与人工复核

真实调用在当次任务已授权的范围内执行。此前文档规划未启动新运行；本轮用户已授权实现及同样十条测试，实际结果见第10节。新实验需冻结同一版本的检测器、局部上下文取样、三个 expert examples、prompt、模型与推理参数，先检查 000543，再完成固定清单的其他九条；配置发生变化时整组结果按新运行记录。

逐节点复核实际发送的候选及其局部上下文、一张示例和模型依据，并结合完整视频检查以下内容：

- 目标形态是否已经在当前候选中成立，夹爪位置是否支持该次折叠刚结束，是否已经开始下一动作。
- 偏晚的 stage1 是否改选到有证据支持的完成候选；缺阶段是否来自无合格候选、模型拒绝/不确定，还是尚未进入该阶段搜索。
- 准备、铺衣和整理是否仍被误选为 stage1；不能只看边界前移或三槽齐全就宣布改进。
- 候选缺失与模型判错是否分别报告；没有精确真值的轨迹只报告定性复核及待确认状态。
