# 单候选 VLM 接口

版本：`node_shape_prompt_v3`；对应 [边界契约](../boundary.md)。实际单一资产为 `src/split_cloth_v2/assets/node_shape_prompt_v3.txt`，每次运行冻结展开文本与摘要。v2 明确返回 JSON 对象；v3 把严格字段类型写入实际请求，特别是整数 `target_stage`。阶段语义保持 `reverse_node_v1`。模型效果以真实运行记录为准。

## 1. 固定 system 文本

```text
你是折衣视频阶段标注员。本次只判断一个候选节点是否符合指定阶段的结束形态。
候选节点已由实测夹爪state检测确定，满足任意一只夹爪张开；无需判断双手是否都释放。

阶段形态：
stage1：单侧袖子及相连侧边向内叠起，另一侧尚未叠入。
stage2：双侧袖子及侧边均已叠入，衣服形成长条。
stage3：长条再次折起，形成小方块状衣物包。
允许皱褶、歪斜和少量边角外露，不要求规则正方形。

以标记为CANDIDATE的帧判断，前后画面按时间正序提供上下文。
排除铺衣、拉伸，以及折好后搬运、放置和空手动作产生的张开节点。
后续画面只能帮助识别动作，不能用之后才形成的形态证明候选帧已完成。
符合当前目标填match，明确不符合填skip，遮挡或证据不足填uncertain。
只返回一个JSON对象，包含当前node_id、target_stage、decision和一句可见依据evidence。
只允许这四个字段。node_id为当前候选ID字符串；target_stage必须是整数1、2或3，不能是"stage3"这样的字符串；decision为match、skip或uncertain字符串；evidence为非空字符串。
不要使用Markdown代码块或添加其他文字。
不得选择其他节点、输出新帧号或一次填写多个阶段。
```

## 2. 每次 user 内容

```text
当前候选：{node_id}
当前目标：stage{target_stage}
返回JSON中的target_stage字段必须是整数{target_stage}。
以下图片按时间正序排列；CANDIDATE是唯一待判断帧。
```

随后按顺序发送各图标签及图片。标签包含 `BEFORE / CANDIDATE / AFTER` 和相对候选时间；本地记录保留原始帧号与 PTS。只输入一个候选的局部窗口，不把前面请求的历史判断追加进来。

首轮工程默认：按实际视频 PTS 抽取相对候选 `[-1.0, -0.5, 0, +0.5, +1.0]` 秒附近的原始帧，越界截断后去重；0 必须精确为候选原帧，不能用附近采样代替。当前帧应清晰突出。窗口跨到其他候选不改变本次唯一待选节点。

不向 VLM 发送原始夹爪数组、另一爪状态、人工帧号、旧预测、数据集任务标签或 reference 示例图。程序已负责事件资格，VLM 只判断视觉形态。图片预算、帧偏移和图像处理参数都写入 run 配置与证据索引。

首版固定窗口，不做 `uncertain` 后的隐式扩图或重问。若后续实验需要扩图，单独配置和记录，不能把同一候选的多次询问藏进一次调用统计。

## 3. 返回格式

以下是结构示例，不是实际模型结果：

```json
{
  "node_id": "n0007",
  "target_stage": 3,
  "decision": "match",
  "evidence": "衣物已横折成短方块，当前位于操作面上。"
}
```

严格限定四个字段：`node_id` 必须等于当前候选，`target_stage` 必须等于当前目标且为整数 1/2/3，`decision` 只能是 `match`、`skip`、`uncertain`，`evidence` 为非空短句。拒绝自由帧号、时间戳、其他节点、`participant_arms` 和额外阶段槽位。

格式检查失败属于执行/接口错误，不等同于衣物不匹配。`evidence` 留给人工核查，程序不使用关键字或第二个模型去偷偷改写 decision。

## 4. prompt 管理

实现时将上述固定文本放入单一 prompt 资产，所有运行加载同一来源；本文保留语义与接口说明，修改资产时同步核对契约。记录最终展开文本和摘要，避免“文档一版、实际请求另一版”。

程序负责倒序与目标切换，无需在每个请求里重复完整搜索算法。阶段定义若修改，应升级 prompt/协议版本并重新运行回归。
