# 主算法完整 MP4 与复核展示

日期：2026-10-30。适用纯 joint 主算法。阶段、边界和缺失语义以 [boundary.md](../boundary.md) 为准。正式导出器为 `src/split_cloth_v2/joint/render.py`，通过仓库 CLI 的 `export-video` 和 `report` 调用。实际导出证据见 DEVELOPMENT。

## 1. 展示内容与来源

输入为原视频、经校验的原帧/PTS 轴、已保存结果、冻结候选及明确选择的标签来源。导出只展示已有结果，不重新推断、训练或移动边界。

默认展示四段 V1–V4，同时提供 S1–S5 动作轨道和固定 b1–b4 槽位：

| 动作阶段 | 含义 | 四段展示 |
| --- | --- | --- |
| S1 | 自由准备整理前缀 | 与 S2 合并为 V1 |
| S2 | 第一个袖子及侧边折入 | V1：准备与第一次折叠 |
| S3 | 第二个袖子及侧边折入 | V2：第二次折叠 |
| S4 | 最后翻折形成短包 | V3：最后翻折 |
| S5 | 搬运、放置、退离与收尾 | V4：移走与收尾 |

四段轨道使用 b2–b4；五段轨道使用 b1–b4。任一轨道所需边界不全时，其逐帧标签和主色带全部未知；已选节点仍可单独标出。b1 缺失而 b2–b4 合法时，可显示完整四段轨道，不能据此补齐五段。

默认结果、无阈值原始假设、Codex 参考和用户确认分别标明来源。若显示原始假设，必须有独立标识，不能冒充正式已接受结果。人工版或参考版使用独立导出名称，不覆盖预测与原记录。

## 2. 画面布局

沿用 1280×720 横向深色画布：左侧原画面等比缩放并保留全视野，右侧为轨迹 ID、阶段、边界、原帧/时间和复核状态，底部为时间线与候选标记。所有文字、边框和时间线置于源画面外侧。

- 四段可沿用青、紫、橙、绿，未知用灰色；五段轨道单独说明颜色和语义。
- 边界列表固定 b1–b4，缺失显示“未确定”，不将后续边界前移填槽。
- 按帧等宽绘制时，边界线位于 `(b+1)/N`，播放游标位于 `(i+0.5)/N`；b 帧仍显示前段，b+1 才切换。
- 标出全部冻结张开候选，区分已选和未选；未选候选不伪造逐节点语义判断。NOW 高亮只在候选原帧出现，邻近信息提示不改变候选帧。
- 显示原帧号、总帧数、源相对秒数、张开侧及节点身份；程序完整、待复核、执行失败与用户确认分别展示。
- 中文字体须可解码显示；缺少合适字体时使用明确的英文标签，避免方框字。

视频正序、原速播放。S5→S2 是搜索顺序，不倒放视频。S5 终态没有视觉确认时显示“未评估”，不暗示放置成功。

## 3. 编码与时间轴

逐源帧合成一个输出帧，保留全片和相对 PTS，不抽帧、补帧或强制统一 20/30 FPS。源起点可归零，但必须记录映射；MCAP 转换和 MP4 时间精度引入的舍入须可追溯。

输出 H.264、yuv420p、1280×720，采用支持完整播放的 MP4 封装。编码器、CRF、preset、time base 等实际参数写入导出记录；不能仅凭名义 FPS 构造时间戳。发现音轨时明确报错；当前导出器不支持音轨，不静默丢弃。

编码先写临时文件，完成并验证后形成最终输出；同名结果不覆盖，重导出使用新名称。失败保留原因，不将临时或不可解码文件计为完成。

## 4. 产物与验证

每个视频保存来源摘要、结果/标签摘要、导出器版本、候选和边界、状态、编码参数、源/输出帧数、最大相对 PTS 误差及输出摘要。汇总索引列出每条视频路径和实际成功/失败状态。

重新解码输出，逐帧核对数量、相对 PTS 和边界切换；时间容差须按实际 time base 明确记录，不只检查文件能打开。抽看每条首末帧、b/b+1 和候选附近，确认源视野、文字与未知提示可读，并检查导出没有改写输入、参考或预测。

后续 10 条 7 轴示范须对应 10 条不同轨迹的完整视频。结果缺边界仍导出待复核版；源损坏则记录执行失败并修复，不能交空视频或以同一轨迹多版本凑数。导出通过与边界质量分别报告。
